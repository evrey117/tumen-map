# Аудит карты Тюмени — 31 октября 2026

## Вывод

Технические функции карты проверены в реальном браузере на публичном сайте; найдены и исправлены ошибки управления черновиком/подтверждения сохранения. Реальные данные 17 ЖК и географические контуры не менялись.

**Достоверность исходных сведений пока недостаточна для использования карты как официального реестра объектов недвижимости и действующей инфраструктуры.** Как инструмент первичного пространственного подбора она работает. Для рекомендаций клиенту требуются адресная/проектная сверка шести приблизительных точек и проверка учреждений по официальным реестрам. Совпадение адреса в OSM не доказывает принадлежность здания ЖК, застройщика, ввод или заселение.

## Методика и безопасность

- Проверены публичные страницы и реальные запросы в Chromium, desktop 1440×1000, mobile viewport 390×700. Это эмуляция экрана, не испытание физического iPhone/Android и не проверка всех браузерных движков.
- Все 17 исходных карточек просмотрены отдельно: название, застройщик, адрес, координаты настоящего L.Marker и поиск по названию. Данные сопоставлены с исходной фикстурой; для каждого источника выполнен свежий Nominatim lookup.
- Реальные первый/второй/третий ответы Nominatim выбраны на публичной карте; координаты слоя, полей и визуального SVG-прицела совпали, экранное смещение 0 CSS px в проверенном сценарии.
- Административные CRUD, отмена и конфликт проверялись в черновиках и временных Git-репозиториях. Синтетические объекты не попадали в main/Pages.
- Изолированный цикл использует настоящий `scripts/manage-homes.mjs`, реальный commit/push в **локальный bare Git**, отдельную HTTP-публикацию и два независимых браузерных контекста. Идентичность владельца в этой модели задаётся тестовыми серверными ID, а не имитирует успешный вход реального владельца в GitHub.
- Отдельный GitHub Actions workflow `audit-storage.yml` имеет только `contents: read`, checkout не сохраняет учётные данные. Проверка опасных операций выполняется там в той же изолированной модели. Фактический запуск [GitHub Actions №41222703883](https://github.com/evrey117/tumen-map/actions/runs/41222703883) завершён успешно: установка браузера, unit-тесты, сборка, безопасный полный цикл и загрузка артефакта прошли.

## Исправления

1. Подтверждение сохранения сверяет реальные эффекты upsert/delete/restore с отправленным запросом. Любой другой SHA больше не считается успехом. При конфликте черновик не теряется.
2. Если после подготовки запроса форма/черновик изменились, старый запрос нельзя случайно скопировать/подтвердить как новый. Дополнительные несохранённые правки не стираются без согласия.
3. Пустое поле координаты не преобразуется в ноль и не перемещает цель за пределы города; ошибочное значение не подтверждается.
4. Безымянные объекты и неполные адреса обозначены явно. В адресах видны другие населённые пункты. Категории названы данными OSM, а центры контуров — не подтверждёнными входами.
5. Для объектов OSM с construction добавлены датированные предупреждения; совпадение адреса не выдаётся за официальную проверку ЖК или сдачи.
6. `landuse=industrial` явно отделён от кадастра, ВРИ, ПЗЗ и санитарно-защитных зон. Опасность, выбросы и действующее производство не выводятся из одного тега.
7. Добавлен favicon, устранён связанный с отсутствующим ресурсом 404; ошибки сети и штатные отмены тайлов разделены в диагностике.
8. CLI не выводит фрагмент некорректного JSON-запроса в лог. Публикации из admin-workflow и ручного Pages приведены к одной очереди без отмены выполняющегося deployment; права доступа не расширены.
